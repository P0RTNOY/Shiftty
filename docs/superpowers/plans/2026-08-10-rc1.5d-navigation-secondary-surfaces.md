# RC1.5D Navigation and Secondary Surfaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the primary navigation to four tabs and make Calendar, Reports, and Settings simple by default while preserving every existing route and underlying domain capability.

**Architecture:** Keep Expo Router URLs and domain hooks intact. Move the legacy Add Shift screen out of the tab route group while preserving its `/add-shift` URL, keep contextual creation actions on Home and Calendar, use local presentation state for report salary details, and add a small Settings hub that joins report exports with backup/restore without duplicating either implementation.

**Tech Stack:** Expo Router 57, React Native, TypeScript, Jest, Testing Library React Native, existing i18n/theme/components.

## Global Constraints

- Do not rewrite the domain, repositories, salary engine, export adapters, or backup orchestration.
- Preserve `/add-shift`, `/shifts/new`, `/settings/exports`, and `/settings/data-management` as working deep-link URLs.
- Primary tabs must be `בית`, `לוח שנה`, `דוחות`, and `הגדרות` only.
- Calendar creation must remain available in month, week, and agenda modes.
- Default Reports must show month, total shift count, total hours, forecast earnings, warnings, and a simple shift list.
- Detailed salary metrics, filters, and breakdowns must be hidden behind `פירוט שכר`.
- Settings must have no visible disabled/dead language or timezone row.
- Every visible Settings row must navigate or perform its described action.
- Use TDD for every behavior change and run the complete repository gate set before commit.
