# RC1.5E Progressive Disclosure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Shift Details and shift editing understandable in ordinary worker language while retaining every scheduled, actual, reporting, recurrence, salary, and recovery capability behind explicit disclosure.

**Architecture:** Keep route orchestration and domain models unchanged. Give `ShiftDetailView` a user-focused primary summary plus local `פרטים נוספים` state, make `SalaryBreakdown` show one salary amount/status before its own detailed disclosure, and move new-shift recurrence controls into the already-existing Shift Form advanced area.

**Tech Stack:** React Native, Expo Router 57, TypeScript, existing domain duration services, Jest, Testing Library React Native, existing i18n/theme/components.

## Global Constraints

- Do not remove or rename domain fields, repository methods, routes, recurrence support, salary snapshots, or calculation services.
- Default worker-facing copy uses `כניסה`, `יציאה`, `התחלה`, `סיום`, `הפסקה`, `מקום עבודה`, `שעות לדיווח`, and `שכר`.
- Default Shift Details must not expose three parallel ranges, recurrence internals, created/updated metadata, engine version, calculated timestamp, or segment multipliers.
- A completed shift defaults to date, clock in, clock out, total, break, workplace, and estimated/final salary.
- Reporting hours may appear in the primary summary only when they differ from actual hours.
- `פרטים נוספים` retains scheduled/actual/reporting comparisons, recurrence marker, notes, and audit timestamps.
- `פירוט שכר` retains pay components, regular/special hours, segments, engine version, calculated time, and recalculation.
- Incomplete and stale salary warnings remain visible without disclosure.
- Edit/New Shift defaults remain simple; reporting overrides, salary overrides, recurrence, roles, templates, and notes remain available under `אפשרויות נוספות`.
- Use TDD for every behavior change and run the complete repository gate set before commit.
